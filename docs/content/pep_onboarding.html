GCP Bucket

Overview

There are some fundamental differences in how we work with data in a bucket versus how we work with data on a local machine or in a shared drive.

  • Data in a bucket are stored as objects, so folders are useful for our organization, but not necessary for the bucket to function.
  • Data in a bucket are not stored on your local machine, so data are downloaded to your local machine or virtual machine when you work with it. This is different than a shared drive, where the data are stored on a server and you can work with the data without downloading it to your local machine.
  • Data in a bucket cannot be modified the same way as files are on a local machine or shared drive.
    • The only actions you can take on data in a bucket are read, write, and delete. No modify!
    • You will need to download the data, modify it, and then upload it back to the bucket. This is different than a shared drive, where you can modify the data directly on the server.
    • This also applies to renaming files, so it’s best to ensure the data are named properly and are organized based on the project protocols before the data are uploaded to a bucket.
    • There is also a cost for each of these actions if done from your local machine.

Based on these fundamental differences in the data, read-write access to the PEP buckets is limited to a small number of staff. Most of PEP only has read-only access to the data in the afsc_mml_pep bucket. The pep_storage bucket is intended to allow for staff to have more flexible access to the data. Contact S. Koslovsky if you need different permissions to the afsc_mml_pep bucket.

Authentication

Authentication for bucket access is now limited to 16-hour time windows, meaning your process will be interrupted if it is actively working with bucket data for more than 16 hours. This is most likely to impact AI/ML training and any potential long-running processes. This is a recent change so more details will be provided about workarounds as more information is available. For now, be aware of this limitation and plan accordingly.

General Guidance

There is no cost to move data into a bucket, but there are costs for storing, accessing, and modifying the data in our buckets when data are pulled to our local machines. When we work with the data from a workstation or virtual machine (that are stored in the same region as our bucket), there is no cost to working with the data (though there is a cost to having a VM or using a workstation). Each program’s costs are heavily monitored, and we will be notified (individually and/or programmatically) if our usage is anomalous. For now, be aware of how you’re interacting with the buckets, and reference this chart as guidance (not authority) to help you get started selecting the right tool you use for connecting to the data.

General guidance when working with data in a bucket:

  • Use your laptop for light access
  • Use a workstation for R, Python, or Visual Studio code development and execution
  • Use a virtual machine if you need access to software beyond those offered from a workstation (e.g. DIVE annotation)

PEP Database

This section details the different methods for connecting to the PEP database using Microsoft Access, R, QGIS, and ArcMap/Catalog/Pro software.

Connect from Microsoft Access

To use any of the PEP database Access front-ends or to create your own connection to the database via Access, you need to have the ODBC connection established. This requires support from an AFSC Service Desk ticket to update your ODBC Data Sources to allow connection to PostgreSQL.

The connection details for setting up the ODBC connection are as follows:

  • Install the ODBC driver with Service Desk Ticket.
    • You will want to download the most recent driver.Click on the most recent folder without “-mimalloc” at the end of the file name; install the psqlodbc_x64.msi version.
    • If you have a new laptop or VM, you will need to submit a Service Desk Ticket. I recommend you work through the remaining steps with OFIS to ensure the correct driver was installed.
    • If you already have this installed (which all staff as of 9/1/2026 do based on past usage of the PEP database), skip to the next step. You do not need to work with OFIS to add the data source.
  • From the start menu, open the ODBC Data Source Administrator (64-bit), click “Add…”.
  • In the list of drivers available, select “PostgreSQL Unicode(x64)” and click Finish.
  • In the PostgreSQL Unicode ODBC Driver (psqlODBC) Setup, enter the following details:
    • Data Source: mml_pep
    • Description: (leave blank)
    • Database: mml_pep
    • SSL Mode: allow
    • Server: afsc.postgres.prod.nmfs.local
    • Port: 5432
    • User Name: your user name
    • Password: your password
  • Before saving, click “Test” to confirm the connection to the database.
  • Click “Save” and close the window.

Once configured, you can open any of the program databases and should no longer need to enter your user name and password each time. Hooray! If you are not experiencing this, you might need to update to a newer version of the ODBC driver.

ONLY AFTER WE MIGRATE THE PEP DASHBOARD: If you have a database connection to the old, internal PEP database (pep), delete that from the ODBC connections list.

Connect from R

To connect to the PEP database from R, there are two different steps:

  1. First, create an .Renviron file to store the connection details to the database. This only needs to be done once.
    1. Create a new text file in your Documents folder on your laptop (typically in C:.LastName) named “.Renviron”. There will be no file name and the file extension is Renviron (weird, I know).
    2. Open the file in a text editor (Notepad or Notepad++).
    3. Enter the following details and save the file.
mml_pep_ip = afsc.postgres.prod.nmfs.local
mml_pep_port = 5432
mml_pep_db = mml_pep
mml_pep_user = your user name (as provided)
mml_pep_user_pw = your password (as provided)
  1. Second, connect to the database during an R working session. You will need to do this each time you connect to the database. The following steps are required:
    1. Ensure you have the RPostgres R package installed. Do not use RPostgreSQL, as it is outdated. If you catch S. Koslovsky sharing this package, call her out! :)
    2. Use the following code to create a connection to the DB using the details in your .Renviron file:
library(RPostgres)
con <- RPostgres::dbConnect(
  Postgres(),
  host = Sys.getenv("mml_pep_ip"),
  port = Sys.getenv("mml_pep_port"),
  dbname = Sys.getenv("mml_pep_db"),
  user = Sys.getenv("mml_pep_user"),
  password = Sys.getenv("mml_pep_user_pw") #,
  sslmode = "require"
)
c. Once you have this connection established, you can use the RPostgres package to get, query and send data to the database. As an example, the following code will return all details for PEP activity plans stored in the database.
data <- RPostgres::dbGetQuery(
  con,
  "SELECT * FROM administrative.tbl_activity_plans"
)

Connect from QGIS

To view spatial data stored in the PEP database:

  • Open QGIS.
  • Right click “PostgreSQL” in the Browser window, and select “New Connection…”. NOTE: If you see “PostGIS” instead of “PostgreSQL”, you need to submit a Service Desk Ticket to update your version of QGIS. You should be working with QGIS 3.28 or higher.
  • In the Create a New PostGIS Connection window, specify the following options:
    • Name: mml_pep
    • Service: (leave blank)
    • Host: afsc.postgres.prod.nmfs.local
    • Port: 5432
    • Database: mml_pep
    • SSL mode: require
    • Username: your user name (check box to save)
    • Password: your password (check box to save)
  • Click “Test Connection” to confirm the connection to the database and before closing the menu.
  • Once created, you will see a new connection to the database under PostgreSQL. The available data are listed under each schema, and only spatial data are visible (unless you have configured your connection otherwise).

For entering or modifying spatial data, process the data as instructed for each individual project. 

Connection from ArcGIS

To view spatial data stored in the PEP database in ArcGIS, you will need to create a database connection. This can be done in ArcCatalog or ArcPro:

  • In ArcCatalog in the Catalog Tree, navigate to the “Database Connections” OR in ArcPro under Insert/Connections. Select “Add Database Connection”.
  • In the pop-up window, select or enter the following details:
    • Database Platform: PostgreSQL
    • Instance: afsc.postgres.prod.nmfs.local
    • Authentication Type: Database authentication
    • User name: your user name (as provided)
    • Password: your password (as provided)
    • Save user name and password: OK to save!
    • Database: mml_pep
  • Once connected, you can view all data and add spatial data to your maps.

Do not make any changes to the spatial data from ArcGIS software. QGIS is our authoritative software for editing spatial data.
